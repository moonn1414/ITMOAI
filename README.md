# ITMOAI

Прогнозирование Attrition сотрудников

Учебный проект по машинному обучению, выполненный в аспирантуре ИТМО. Проект исследует, можно ли по признакам из публичного HR-датасета прогнозировать метку `Attrition` — факт увольнения сотрудника в датасете — и какие признаки наиболее связаны с прогнозом модели.

> Это учебная работа на публичных данных. Модель не является production-решением и не предназначена для автоматического принятия кадровых решений.

## Задача

В условиях текучести компании важно понимать, какие группы сотрудников требуют дополнительного внимания. В проекте сформулирована задача бинарной классификации: по характеристикам сотрудника и условиям работы предсказать значение `Attrition` (`Yes` / `No`).

Поскольку класс увольнений в датасете несбалансирован, качество моделей оценивалось не только по accuracy, но и по precision, recall и F1-score для положительного класса.

## Данные

Использован публичный [HR Analytics Prediction dataset на Kaggle](https://www.kaggle.com/datasets/rishikeshkonapure/hr-analytics-prediction/data). В ноутбуках данные загружаются из локального CSV; файл с данными в репозиторий не включён.

Перед моделированием я:

- проверил структуру данных, дубликаты, распределения и связи признаков;
- исключил константные и неинформативные поля;
- закодировал категориальные признаки;
- разделил выборку на обучающую и тестовую с `random_state=8`.

## Что сделано

1. **Постановка задачи и EDA.** Определил целевую переменную, выбрал метрики, изучил распределение классов, взаимосвязи и признаки, которые можно использовать для модели.
2. **Baseline и простые модели.** Сравнил `DummyClassifier`, дерево решений и логистическую регрессию; для логистической регрессии дополнительно применил стандартизацию признаков.
3. **Работа с дисбалансом классов.** Для пайплайна с Random Forest использовал `RandomOverSampler` внутри `imblearn.pipeline`: oversampling применялся к обучающим данным, а тестовая выборка оставалась нетронутой.
4. **Подбор гиперпараметров.** Проверил варианты Random Forest через `GridSearchCV` с 5-fold cross-validation и метрикой `f1`; отдельно провёл поиск через Optuna. Конфигурация в блоке результатов — отдельный воспроизводимый эксперимент, а не заявление о единственной «лучшей» модели.
5. **Интерпретация.** Построил permutation importance и визуализации поиска гиперпараметров. Важность признака интерпретируется как его связь с предсказанием модели, а не как причинный эффект на увольнение.

## Результат

Для зафиксированной в ноутбуке модели `RandomOverSampler + RandomForestClassifier(max_depth=6, n_estimators=60, random_state=8)` на тестовой выборке получены:

| Модель / метрика | Значение |
|---|---:|
| `DummyClassifier`, Accuracy | 0.8537 |
| `DummyClassifier`, F1-score для класса `Attrition=1` | 0.00 |
| Random Forest pipeline, Accuracy | 0.8129 |
| Random Forest pipeline, Precision для класса `Attrition=1` | 0.41 |
| Random Forest pipeline, Recall для класса `Attrition=1` | 0.63 |
| Random Forest pipeline, F1-score для класса `Attrition=1` | 0.50 |

Результат показывает учебную проверку ML-пайплайна, а не готовность модели к внедрению. Для прикладного использования потребовались бы уточнение бизнес-стоимости ошибок, выбор порога классификации совместно с HR, проверка стабильности на новых данных и оценка fairness.

## Как запустить

1. Скачайте публичный Kaggle-датасет. В первых двух ноутбуках ожидается файл `HR-Employee-Attrition.csv`, а в третьем — `HR-data.csv`; перед запуском приведите имя файла в коде к одному варианту.
2. Откройте ноутбуки последовательно: `HW_ML1_v1.2.ipynb` → `HW_ML2 v.1.1.ipynb` → `HW_ML_3_v_2_0.ipynb`.
3. Запустите их в Google Colab или локально, предварительно установив библиотеки из раздела «Стек».
